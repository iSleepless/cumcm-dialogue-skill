# AI 工具使用报告：整理与填写指南

本指南采用用户提供报告中的“三部分”结构：工具信息、关键交互记录、总体说明与责任。具体题目、工具型号、日期和参与范围由真实记录填写。

## 1. 可用文件

- [使用日志](../assets/ai-usage-log.md)：在对话过程中记录用途、采用与复核状态。
- [Markdown 报告模板](../assets/ai-use-report-template.md)：便于汇总、审阅和转换格式。
- [LaTeX 报告模板](../assets/ai-use-report-template.tex)：保留居中标题、工具信息、分条交互和边框形式，使用 XeLaTeX 编译。

模板没有默认的实际工具型号、日期、研究方法或“全部独立完成”结论。所有“待填写”字段是填表提示，不是已发生的事实。

## 2. 填写顺序

1. 读取适用竞赛年份的官方规则，确定声明位置、报告字段和详细程度。
2. 汇总真实日志或可核验的对话摘要，确认工具、时间与用途。
3. 按参与环节归类，可包括题意理解、方案讨论、模型建议、推导检查、代码、数据、图表、文字、排版和材料整理。
4. 选取有代表性的交互，说明输入、输出摘要、采用范围、人工修改和实际复核。
5. 总体说明覆盖所有实际参与环节，不能因只列几条记录而遗漏建模或代码等实质用途。
6. 核对报告、论文声明和支撑材料的描述是否一致，再按要求导出。

## 3. 字段如何填写

| 字段 | 填写依据与注意点 |
|---|---|
| 工具名称、服务商 | 按实际使用；多工具分别列出 |
| 版本/型号 | 根据界面或使用记录；不清楚则写未记录，勿照搬样例型号 |
| 使用日期/阶段 | 实际时间范围；不明确时说明记录缺口 |
| 使用环节 | 如实说明是模型讨论、代码生成、排错、图表还是文稿辅助 |
| 提示词/关键回复 | 可用摘要，标明概述，不伪装成逐字引用 |
| 采纳与修改 | 说明哪些内容被采用、调整或拒绝，以及落在哪些文件 |
| 核验方法及结果 | 仅列实际执行的检查；未完成写待核验，不写已通过 |
| 总体范围与责任 | 覆盖真实参与，区分团队最终决定与 AI 的辅助建议 |

没有记录的细节不得补造。需要说明记录不完整时，保留“未记录/待确认”并由用户补充。

## 4. 简洁与详细两种写法

**简洁版：**少量代表性交互，加一段覆盖实际参与范围的总体说明。适用于规则允许且日志范围不大时。

**详细版：**按阶段列多个记录，保留相关文件、采用情况与核验结果。适用于有较多模型、代码、图表或写作辅助的项目。

两种写法只改变详略，不改变实际发生的参与事实。用户要求“简化”或“写几个问题”时，可以压缩和合并记录，不能把模型讨论改写成仅排版，也不能把 AI 生成代码说成完全手工编写。

## 5. 从日志到报告的通用提示词

```text
请依据本项目的真实 AI 使用日志，按“工具信息—关键交互记录—
总体使用范围与责任说明”的结构编写报告。

每条交互说明使用环节、提示内容、关键回复摘要、采用与修改、
关联文件以及实际复核方法和结果。可以选择代表性交互，但总体范围
必须包含所有实质用途。未知的型号、日期、记录和核验结果标为未记录或待确认，
不要按样例补造，也不要预先写成“核心工作未使用 AI”。
格式沿用提供的模板，篇幅按规则与本项目需要调整。
```

## 6. LaTeX 编译与版式检查

该 `.tex` 模板需 XeLaTeX、中文支持、`geometry`、`xcolor`、`mdframed` 和 `hyperref`。在能正常读取中文字体的 TeX 环境中，可将模板复制为项目报告文件，再填写并编译。

模板的 A4、12pt、黑色边框是可修改的初始版式，不是所有竞赛或论文的固定要求；按对应规则和用户模板调整。

填写路径或含 `_`、`%`、`&` 等字符的内容时，按 LaTeX 语法转义，避免把可运行模板改坏。长记录在边框内可分页；填完后检查跨页边框、标题、换行和页码。

模板的渲染通过，只证明空模板可排版，不代表某份实际报告已满足赛事要求或内容真实。最终报告须核对真实记录与规则。

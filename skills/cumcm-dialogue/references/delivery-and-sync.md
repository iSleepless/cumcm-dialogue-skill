# 官方结果、支撑材料与在线同步

## 官方 Excel：结构与映射分别核验

先读取官方母版，不用自定义工作簿覆盖。确定原有工作表、题头、单位、日期、时间标签、样式、合并区域、固定行列和数据填充单元格。

建立显式映射：`日期 + 物理时段 + 量类型 → 模板坐标`。抽查首日、指定日期、末日、跨日槽位、总量与费用。行号相同不代表时间含义一致。

区间能量与点时刻库存不同；四小时充放电汇总按题设范围，日初/日末 SOC 写在正确时刻位置。

**不要将源文件中的空公式缓存当作已计算数值。** 读 `data_only=True` 前确认已重算/缓存存在，或直接读取程序生成的正式结果；零值有实际来源，不能用零代替缺失。

若模板存在省略号或少量日期样例，而要求完整年度输出且禁止新增行：列出缺少的日期/行容量，并确认正式填写规则。固定结构输出只含示例日期时不能声称全年完整。可保留官方填表版与全量审计版，但两者功能必须明确，并按用户/赛事允许的方式提交。

`scripts/audit_official_xlsx.py` 是只读结构审计工具：

```text
python scripts/audit_official_xlsx.py template.xlsx result.xlsx
python scripts/audit_official_xlsx.py template.xlsx result.xlsx --allowed-ranges fill-ranges.json
```

`fill-ranges.json` 按工作表列出允许修改的结果区域。例如：

```json
{"计划购电量": ["B2:D10"], "充放电量": ["C2:D7", "F2:F3"]}
```

填写范围必须从实际模板确定，示例不能照搬。默认保留全部原有非空值，允许向空白单元格写值；提供范围后也检查新增数值是否落在范围内。脚本检查工作表、行列尺寸、合并区域、单元格样式和题头等固定值，仍不替代日期覆盖、数值来源和物理核验。

退出码 `0` 为上述结构和单元格规则通过，`1` 为失败，`2` 为仍需审查（例如省略号占位或公式缓存缺失）。结构通过不能写成全部结果合规；宏工作簿与嵌入对象不在此辅助脚本的审计范围内。

## 支撑材料可运行性

以需求确定目录，通常含清洗/模型/导出代码、作图代码、正式结果、数据说明、运行依赖、README 和必要 AI 使用报告。

“完整代码”包含被入口导入的模块、配置、依赖和运行顺序。只复制论文代码节选或把旧版脚本命名为完整代码不满足复现。

核对目录名和实际文件，避免 `code/`、`代码/`、`results/` 等说明与工程不符。原始附件如不允许随包公开，提供其预期位置与取得方式。

从干净运行目录做有代表性的复现，指出仍需用户原始附件、求解器或商业软件的部分。整理结果 manifest：模型/配置版本、运行入口、评价日期、结果位置、图表引用及文件校验值。

不要因为换了一种导出格式就选用旧策略结果。相同问题有多个版本时，按正式模型与论文结果核对来源。

## TeXPage 或其他在线 LaTeX

用户提供项目并授权修改后，可沿本次授权同步。先确认实际可用的连接和登录状态；页面 URL、截图或已打开浏览器不代表具备编辑接口。

同步前保留可恢复源版本，确认目标项目、主编译文件、实际内容入口及图资源依赖。对本次已授权文件上传/修改，避免触碰无关项目。

同步验证按层记录：

1. 文件发送/上传是否成功，是否被自动重命名。
2. 在线保存源码是否等于目标版本，主文件是否引用它。
3. 在线编译是否成功，日志与目标图表页是否对应。
4. 刷新后内容是否持久化，是否有并发编辑/旧主文件/缓存问题。

显示本地参考 PDF 并不证明在线源文件可以编译出同样效果。页数相同也不是充分证据。

接口不可用、登录缺失或审批阻止时，完成本地授权工作并如实报告在线尚未完成。用户自行处理身份验证；不读取 cookies、密码或 token 来绕过连接限制。

## AI 工具使用说明

编写或整理报告时读取 [AI 报告填写指南](ai-use-report.md)，按真实日志填入其 Markdown/LaTeX 模板；需要记录后续交互时使用指南中的日志模板。

以真实使用日志记录工具名、已知版本、使用日期、用途、具体交互摘要、采用/修改情况和核验方式。工具版本没有记录就写未记录；模板里的 DeepSeek 名称或某个型号不是本项目使用证据。

可以只列代表性交互，但若 AI 参与题意分析、候选模型、算法实现或写作，范围说明应覆盖这些环节；不能为了“弱化”写成仅排版或“核心工作未使用 AI”。说明团队核验与责任，也不要虚构已经进行的人工作业。

按用户提供或查证的当年赛事规定安排声明和支撑报告位置；不能把历史规则默认成当前要求。

## 交付状态用证据表述

明确哪些文件已生成、已编译、已核验模板、已复现、已上传并持久化。对于未核验部分说明具体缺口，避免只写“已全部完成”。

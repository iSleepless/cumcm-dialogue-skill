# 对话式数学建模全流程 SOP（通用版）

SOP 是 Standard Operating Procedure，即标准作业流程。本文件用于把“人与 AI 共同推进数学建模”的对话转化为可执行、可核验、可恢复的工程过程。

适用于不同主题和不同问题数量的建模竞赛、课程设计及训练。国赛使用时以当年官方规则为准；其他场景采用对应提交要求。城市、研究对象、模型、评价期、色系和在线论文平台均由本项目资料决定。

## 1. 开始前明确目标和工作边界

先判断本轮要求是读题、解释方案、计算、写作、作图、整理交付还是续做工程。用户只要求读材料时，不直接求解；只要求解释模型时，不擅自写成最终论文。

所有后续工作围绕三条对应关系展开：原题要求对应模型条件；模型对应可运行程序；程序输出对应正文、图表和交付文件。对缺失信息标明未确定，不用经验数字补齐结果。

完整项目可能交付以下内容，具体取决于题设和用户要求：

- 各问题意解读、变量假设与建模路线；
- 数据字典、预处理记录、质量审计与可复现代码；
- 模型、求解/估计过程、正式结果及必要的验证；
- 结果表、图源和作图代码；
- 论文源文件、编译稿、附录与支撑材料；
- 当年规则要求的 AI 使用声明和使用记录。

在线同步、公开发布和最终竞赛提交分别确认目标及授权范围。已有授权和已确认偏好在本项目中沿用，避免重复询问。

## 2. 建立项目入口与状态记录

已有工程沿用其目录；新工程可参考以下组织方式，名称不必固定：

```text
project/
  data/raw/                 原始附件，只读保存
  data/clean/               建模输入与字段说明
  results/                  正式计算、审计和官方填写结果
  scripts/                  预处理、逐问求解、导出和制图代码
  paper/                    论文源文件、图件和引用
  docs/                     题意约定、项目状态与检查记录
  supporting_materials/     最终支撑材料
```

使用 [项目状态模板](../assets/project-state.md) 记录当前阶段、资料入口、模型版本、结果位置、已确认选择、用户审阅方式及下一步。模型、图表和论文变更后同步记录，不仅记录聊天摘要。

为每问保留 [单问任务约定](../assets/problem-contract.md)，用于核对题意与实际实现。

### 可选项目配置

| 配置项 | 从哪里确定 |
|---|---|
| 问题数量、研究对象和目标 | 原题与用户当前任务 |
| 训练/验证/测试/正式评价区间 | 数据可用时刻、题设和评价设计 |
| 字号、页眉页码、目录、摘要篇幅 | 官方要求、用户模板或已确认偏好 |
| 色系、字体、单图/分面、矢量格式 | 用户视觉要求与图的表达需要 |
| 附录代码范围、表格位置、分页 | 题设、模板和用户最终约定 |
| 在线平台及同步方式 | 可用工具、目标工程和授权 |
| AI 声明位置与报告字段 | 对应年份的官方规则与真实记录 |

某次项目的固定色系、模型名称、字数、四问结构或初值不转化为所有题目的默认条件。

## 3. 阶段 0：资料接收与题意解读

**输入：**题目、公共条件、附录、数据说明、官方结果模板和已有成果。论文模板、参考论文与视觉偏好可在相应阶段补充。

**执行：**逐条提取每问目标、可用附件、变量单位、决策时点、约束、初末状态、评价区间和指定输出。特别检查相邻小问哪些条件相同、哪些新增信息只限当前小问。

**产出：**问题清单、资料清单、交付义务表与真正影响算法的歧义。

**验收：**能说明“要研究什么、什么信息能用、什么必须满足、最后交什么”。

```text
这是赛题、附件和已有工程。请先逐问解释，不要急着求解。
列出目标、已知信息、约束、单位和必须交付的表格/文件，
把影响建模的歧义集中说明。
```

## 4. 阶段 1：建立可解释的模型路线

**输入：**已确认题意与数据条件。

**执行：**将第 k 问写成研究目的、变量、假设、模型关系、评价标准、预期产物和验证方法。先说明为什么这个数学问题适合当前方法，再安排必要的有限比较。

描述统计、关联、反演、预测和优化各自需要不同证据。不能因为某个算法常见、名字新颖或上一题用过，就直接复用到当前题。

**产出：**单问任务约定、正式方案和必要的备选方案。

**验收：**变量、参数和约束有现实含义；模型可以对应到程序；重要假设的影响能说明。

```text
先理清第 k 问：目标是什么，变量和假设是什么，关系式如何建立，
为何选择这个模型，用什么指标和核验回答原题？暂时只讨论方案。
```

用户确认方案后固定版本。探索新思路时保留正式版本，避免新结果覆盖已确认的论文数值。

## 5. 阶段 2：数据预处理与质量审计

**输入：**原始数据、单位说明、主键与研究范围。

**执行：**核对字段、单位、时间戳含义、重复、缺失、异常和覆盖范围；按研究对象筛选、对齐和聚合；记录每步样本数量变化及处理依据。

区间平均功率转电量按持续时间计算；其他单位换算也应显式记录。预测任务的插值、标准化和统计特征只能使用其训练或决策时已知信息，不能引入未来实测。

原始记录保留；填补和异常处理有标记。不存在通用的“全部负值删除”或“短缺失必插值”规则，应先判断变量含义。

**产出：**建模输入、字段字典、预处理脚本和质量审计。

**验收：**研究范围正确，主键与时间对齐清楚，样本数量可追踪，处理后的数据能从原始附件复现。

```text
请按已确认题意建立建模数据，并说明筛选、单位换算、对齐和缺失处理。
输出数据字典、质量审计和完整代码；先报告样本量、覆盖、重复与缺失，
再决定是否进入求解。
```

## 6. 阶段 3：逐问建模、求解与结果验证

每一问按需要推进：

```text
解释目标与信息 → 定义模型 → 编写最小可运行程序 → 实际求解
→ 核验约束与评价 → 必要对比/敏感性 → 固定结果版本
```

**模型建立：**定义符号和单位，列出数学关系、目标与约束，解释关键式子。原题条件与新增假设区分。

**求解过程：**给出算法输入、步骤、求解器/软件、参数依据和停止标准。程序保留为复现入口，文字仍需说明求解逻辑。

**结果验证：**优化任务检查守恒、边界、可行性、求解状态与适用的最优性证据；预测任务检查时间边界、基准和留出/滚动评价；统计任务检查估计条件与结论强度。

初值有依据，跨期状态连续。长期目标不能以每天免费重置库存实现。正式在线回测中，训练、误差库与策略选择仅使用当时已知数据。

**产出：**实际代码、正式结果、指标、约束/统计核验和局限性说明。

**验收：**每个结果能定位到运行产物；零值与反常结果解释经过检查；全局最优、因果或稳健性措辞不超过证据。

```text
按第 k 问已确认方案运行。分别给模型、求解步骤、主要和必要中间结果。
检查题设约束、结果合理性与评价设计，保留正式代码和结果版本。
```

## 7. 阶段 4：论文组织与详细撰写

**输入：**稳定的模型、正式结果、数据审计、题设输出要求和论文模板。

**执行：**沿用用户模板，以“分析—模型建立—求解方法—求解结果—结果分析”为单问主线。写作详见 [通用论文撰写提示词](paper-writing-prompts.md)。

核心结果默认出现在相应正文，不把代码或全量工作簿当作论文结果。用户要求集中到附录或长表需要移入附录时，正文保留主要结果并明确引用，仍逐项满足题面“论文中给出”的要求。

在结果稳定后写标题、摘要和关键词。摘要使用“背景与数据—各问方法及关键结果—总体结论”的结构，段数取决于实际问题数量。字数、加粗、关键词和摘要页要求按配置。

**产出：**有解释、有公式、有求解过程及结果的论文源稿。

**验收：**模型位置明确，主要公式有文字解释；每问和小问输出完整；数字与程序、图表一致；参考文献真实且与引用相关。

```text
请依据正式模型和结果撰写论文，沿用我的模板。
先分析，再建立模型；模型与求解分开，完整说明算法过程、结果与实际意义。
摘要最后写，数值从当前结果来源提取。
```

## 8. 阶段 5：科学图表与审核迭代

**输入：**图要支持的论点、真实数据、图件规格和用户审阅要求。

**执行：**确定颜色语义、字体、最终尺寸和格式；依据数据结构选择图型；生成后渲染检查文字、图例、箭头、单位、留白、遮挡与裁切。流程图表达方法，结果图表达真实计算。

需要逐图审核时，以“待审核—采用/拒绝/跳过—已替换—已编译”记录状态。只改配色或版式的请求保留数值来源。图型多样化以表达清晰为前提。

**产出：**图源、作图脚本、独立图件和对应正文衔接。

**验收：**图中的每个数值、标签和空间关系有依据；图号、图注与正文一致；候选图是否替换与用户决定一致。

```text
先生成一张候选科研图，给出数据来源、图意、拟插入位置和衔接文字。
按已确认色系和字体制作，渲染检查后给我审核；确认后再替换。
```

## 9. 阶段 6：编译、官方填表与在线同步

论文编译后检查页面，重点看长公式、长表、单位、跨页标注和图件。编译成功与版面正确分别核验。

官方 Excel 以母版为准，先明确日期/时段/变量到单元格的映射，再填允许区域。结构一致、日期覆盖完整、数值正确分别验收；模板示例行和完整输出冲突时依据明确填写规则处理。

在线修改前确认可用工具、目标项目、主编译入口和保存状态。上传、保存、在线编译和刷新持久化分别核验。平台可按项目选择；没有接口时如实说明本地已完成、在线未完成。

```text
请核对题设指定日期表和官方母版，填写对应结果，不擅改题头。
已授权的在线文件可同步；完成后分别说明保存、编译与刷新验证结果。
```

## 10. 阶段 7：附录、支撑材料和 AI 使用记录

附录范围与分页遵循项目配置。正文保留必要论证；核心片段标明节选；完整代码、依赖、配置、入口和结果位于支撑材料。

README 的目录、运行顺序和结果对应关系与实际文件一致。原始附件如无法公开，说明其取得与预期位置；不公开用户凭据、个人信息或受限数据。

从实际交互记录生成 AI 声明和报告。使用 [报告填写指南](ai-use-report.md)、[持续使用日志](../assets/ai-usage-log.md) 与 [报告模板](../assets/ai-use-report-template.md)，按规则确定位置及详细程度。

```text
整理支撑材料：完整运行代码、依赖、图源、结果表和文件清单。
依据实际 AI 使用日志编写报告，保留采用范围、修改和核验状态。
```

## 11. 阶段 8：终稿验收

### 题意与模型

- [ ] 每问目标、硬条件、信息边界和指定交付均已回答。
- [ ] 单位、时间索引、初末状态和跨期约束一致。
- [ ] 训练、调参和评价设计符合可用信息边界。
- [ ] 求解/统计/预测验证支持当前结论强度。

### 结果与论文

- [ ] 主要和必要中间结果完整，指定日期与单位正确。
- [ ] 正文、摘要、图件、官方表和支撑材料来自同一正式版本。
- [ ] 公式、算法过程和结果均有必要解释。
- [ ] 文献真实；长表、长公式、字体和图件经过渲染检查。

### 交付与恢复

- [ ] 完整代码及依赖有复现说明，实际文件与清单一致。
- [ ] 官方模板结构、数据覆盖和数值映射分别核验。
- [ ] AI 声明符合真实使用记录与适用规则。
- [ ] 本地与在线完成状态明确，项目记录已更新。

根据真实证据列出通过项、未核验项和阻塞项，不能用一个“检查全部通过”替代未做的检查。

## 12. 新会话的通用恢复指令

```text
请读取本项目的项目状态文件、单问任务约定和正式结果清单。
核对论文、代码和结果的实际版本，保留已经确认的方案与审阅偏好。
不要重复已完成工作，从第一个未完成的必需步骤继续。
```

本 SOP 不固定某个题目、某个算法或某份历史结果；按具体任务选择阶段，并在工程文件中保持决定和产物可追溯。

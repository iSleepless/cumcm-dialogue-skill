# 对话式国赛数学建模 Skill

**让 AI 按照“读懂题目 → 讨论方案 → 实际计算 → 核验结果 → 写论文和交付”的顺序，与你一起推进全国大学生数学建模竞赛。**

你可以先让它解释一道题，再讨论某一问的方法；确认后运行代码，拿到结果后再写论文、画图和填官方表格。过程中说“先别算”“继续下一问”“这张图不用，换下一张”，助手应根据当前阶段和已确认要求继续。

本 skill 提炼自多次空气质量与微网问题的人机协作，重点记录了真实交互中容易遗漏的约定：哪些数据当时可用、公式和代码是否一致、图表是否先审核、官方模板能否修改、在线论文是否真的保存。公开内容均已匿名化。

## 1. Skill 是什么？它如何起作用？

Skill 是给支持该机制的 AI 助手读取的一组任务说明文件。这里的入口是 [`SKILL.md`](skills/cumcm-dialogue/SKILL.md)，安装后可以通过 `$cumcm-dialogue` 调用。

助手读取它后，会根据你当前的请求选择需要的阶段指南，结合你提供的赛题、附件和工程文件开展工作。例如：你要求“先解读”，它就整理题意；你要求“执行”，它才使用已有工具编写、运行和核验程序。

这个仓库提供的内容分为三类：

| 内容 | 实际作用 |
|---|---|
| 工作说明与阶段指南 | 指导助手怎样读题、讨论模型、检查结果、写论文和处理交付 |
| 项目记录模板 | 记录已确认条件、正式模型版本、结果位置和下一步，方便中断后继续 |
| Excel 审计脚本 | 检查官方工作簿题头、行列、合并单元格、样式和允许填写的区域是否被改变 |

**模型代码需要根据你的具体题目另行编写。** 本仓库没有内置可直接套用到任意赛题的 HGB、MILP 或储能求解程序，也没有内置原始竞赛数据。计算、制图和在线修改所需的工具，由你使用的助手环境提供。

## 2. 它与普通提示词、单个算法库有什么区别？

| 使用方式 | 通常解决什么问题 | 本 skill 提供的组织方式 |
|---|---|---|
| 一段普通提示词 | 表达这一轮想让 AI 做什么 | 将反复使用的建模约定保存为可复用文件，并按阶段读取 |
| 单个算法或代码库 | 实现某种算法，例如回归或线性规划 | 指导什么时候适合用它、需要哪些信息、怎样验证，以及如何写进论文 |
| 本 skill | 组织人与 AI 的建模协作 | 同时连接题意、数据、程序、结果、图表、论文和最终交付 |

它的主要价值是提高过程的一致性与可追溯性。实际效果仍取决于基础模型、工具、数据质量和团队核验，不能保证获奖、全局最优或某次策略一定更省钱。

## 3. 每个阶段，你能拿到什么？

你可以从任何已有阶段进入，不必每次从头开始。

| 阶段 | 你可以怎样提问 | 助手应产生的结果 |
|---|---|---|
| 读题与资料检查 | “先读所有附件，不用作答。” | 各问目标、输入输出、条件差异、缺件和待确认歧义 |
| 模型讨论 | “先理清问题二思路，解释数学逻辑。” | 变量、假设、目标、约束、可用信息和方法选择依据 |
| 编码与求解 | “按已确认方案执行。” | 可运行程序、实际计算结果、约束与评价核验 |
| 方法比较 | “这个结果为什么比前一问更差？” | 检查比较口径、信息使用、费用组成和必要的策略对比 |
| 论文撰写 | “按我的模板把模型写详细。” | 模型建立、求解过程、结果解释及题设要求的指定日期表 |
| 图表审阅 | “每张图先给我看，确认后再替换。” | 单张候选图、数据来源、拟替换位置及上下文衔接文字 |
| 正式交付 | “整理代码、官方 Excel 和支撑材料。” | 文件清单、运行说明、模板核验及真实 AI 使用记录 |
| 工程恢复 | “继续昨天的任务。” | 核对项目记录和文件，从未完成步骤继续 |

其中“实际计算”以代码运行成功和结果文件为依据；“在线同步完成”以保存、在线编译和刷新后的内容核验为依据。

## 4. 开始前要提供哪些资料？

通常准备赛题原文、题目附件、数据说明和官方结果模板。进入论文阶段时，再提供 LaTeX 模板、参考论文和你的图表/版式偏好。

不齐全也可以开始。助手应先说明哪些内容能确定、哪些计算需要补件，而不是补造缺失数据或直接写最终结论。

给助手一个明确的工程目录，并说明已有成果。例如：“问题一已完成，正式结果在 results/q1/；现在只讨论问题二。”这样更容易避免重算、误用旧版本或覆盖已确认文件。

## 5. 安装与第一次使用

### Codex：让助手安装

将这段话发给具备 `skill-installer` 的 Codex：

```text
请使用 skill-installer 从下面的仓库安装 skills/cumcm-dialogue：
https://github.com/iSleepless/cumcm-dialogue-skill
```

安装后，按客户端提示刷新或重新开启会话，再用 `$cumcm-dialogue` 调用。

确认安装时，可让助手给出 `cumcm-dialogue` 的入口文件路径并读取其说明。若无法找到入口，先核对安装目录；若文件存在但本轮未采用，明确使用 `$cumcm-dialogue` 调用。

### 手动安装

下载或克隆仓库，将完整的 `skills/cumcm-dialogue/` 文件夹放入客户端支持的 skills 目录。Codex 常见位置为 `~/.codex/skills/cumcm-dialogue/`，Windows 对应当前用户目录下的 `.codex/skills/cumcm-dialogue/`。

安装后的入口应为 `skills目录/cumcm-dialogue/SKILL.md`；保留其旁边的 `references/`、`assets/` 和 `scripts/`，不要只复制 README。

其他客户端以其 skill 安装规则为准。普通聊天环境也可以阅读这些说明来讨论方案，但能否读取本地附件、运行代码或控制网页，取决于环境提供的工具。

### 第一条对话可以直接复制

```text
请使用 $cumcm-dialogue 协助我完成这道国赛题。
赛题和附件已提供，工程目录为当前项目目录。

先逐问解释目标、约束、单位、可用信息和要求提交的文件。
列出真正影响建模的歧义，暂时不要求解或写论文。
```

## 6. 一段完整的交互示例

以下为匿名化微网任务示例，展示对话如何推进，不代表任何赛题的既定解。

**你：**“问题一先给我具体思路，解释功率和电量怎么对应。”

**助手应做：**核对原题时间戳与单位，解释十分钟区间电量如何从平均功率换算，列出目标、储能状态和约束，再给出适合题设的求解方案。

**你：**“这个思路固定，开始运行。问题二先讨论，别着急算。”

**助手应做：**运行并核验问题一；记录已确认方案。问题二只讨论新信息条件，不直接启动全年计算。

**你：**“附件有全年真实数据，能不能直接训练，然后预测二月开始的每天？”

**助手应做：**区分事后规律探索和在线回测。若声称每天零点做实际可实施决策，训练、误差统计和策略选择只能使用当时已知的数据，不能提前使用年末记录。

**你：**“按这个方法执行，论文里的模型要逻辑清楚；图一个一个给我审核。”

**助手应做：**编写并运行模型，导出结果，再按变量—目标—约束—求解—结果解释组织正文；每次展示一个候选图，获准后替换。

**你：**“这张图不用了，做下一张。最终 Excel 的题头和行数不能变。”

**助手应做：**记录当前候选不采用，继续下一张；以官方模板核对填写区域。如果示例日期和省略号不能容纳完整结果，明确指出冲突，不能只检查行数就宣布全部合规。

**你：**“继续昨天的任务，别重复已经做完的。”

**助手应做：**读取项目状态与现有文件，确认正式模型和产物版本，从下一项未完成工作继续。

## 7. 从我们实际交互中提炼了哪些细节？

- **“先读”和“执行”有不同含义。** 用户可以只要解释、先固定一种思路、或指定只修改某张图。
- **多问的信息条件分别核对。** 后一问新增的预报或价格信息，不自动进入前一问。
- **预测效果与最终目标分别评价。** 误差小未必费用最低；多出的信息也需要经过正确的策略设计才能产生收益。
- **结果保持同一来源。** 更新模型后，摘要、正文表、图件和官方工作簿都检查是否仍对应正式结果。
- **图表逐张迭代。** 保留采用、拒绝、跳过等状态；审核过程不应误替换正式图。
- **模板结构和数据覆盖分开检查。** 官方题头未变，不代表全年结果完整或时间映射正确。
- **论文同步逐步验证。** 本地已完成、文件已上传、在线已保存、编译通过和刷新持久化分别记录。
- **AI 使用记录按事实编写。** 可以简洁整理，工具、版本与参与环节仍要有真实依据。

## 8. 长对话中怎样接着做？

skill 提供 [`project-state.md`](skills/cumcm-dialogue/assets/project-state.md) 模板。让助手把已确认条件、模型版本、结果位置、图表审核和下一步记到你的工程目录。

```text
请更新本项目的项目状态文件，记录已完成工作、正式结果版本和下一步。
下次继续时，先读取这份记录并核对实际文件。
```

它通过文件帮助恢复工程状态，不会自动获得其他聊天的内容或无限保存记忆。恢复时需要能访问这些记录和对应文件。

## 9. 仓库文件分别有什么用途？

| 文件或目录 | 用途 |
|---|---|
| [`SKILL.md`](skills/cumcm-dialogue/SKILL.md) | 助手的入口说明、阶段路由和关键工作约定 |
| [`references/`](skills/cumcm-dialogue/references/) | 题意数据、模型验证、论文图表、交付同步的详细指南 |
| [`assets/`](skills/cumcm-dialogue/assets/) | 可复制到工程中的项目状态、单问任务约定、AI 使用日志和报告模板 |
| [`agents/openai.yaml`](skills/cumcm-dialogue/agents/openai.yaml) | Codex 可选的 skill 名称、简述和默认调用提示 |
| [`audit_official_xlsx.py`](skills/cumcm-dialogue/scripts/audit_official_xlsx.py) | 只读检查官方工作簿结构与单元格修改规则 |
| [`tests/`](tests/) | 用合成工作簿验证审计脚本，不包含参赛附件 |

阶段指南按当前任务读取，避免每轮加载全部内容。详细示例见[匿名对话案例](skills/cumcm-dialogue/references/dialogue-cases.md)。

新增配套资料分别位于 `references/general-sop.md`、`references/paper-writing-prompts.md`、`references/ai-use-report.md`；报告与使用日志模板位于 `assets/`。它们包含在完整技能文件夹中，安装时一起保留。

## 10. 脚本使用与验证范围

执行 Excel 审计需要 Python 3.10+ 和 `openpyxl`。下列命令适用于下载或克隆了**完整仓库**的开发者，在仓库目录运行；日常使用 skill 不必运行这些测试：

```sh
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python skills/cumcm-dialogue/scripts/audit_official_xlsx.py template.xlsx result.xlsx
```

若只安装了技能文件夹，审计入口是该文件夹内的 `scripts/audit_official_xlsx.py`，安装 `openpyxl` 后可单独运行。`tests/` 和 `requirements-dev.txt` 属于仓库开发文件，无须一起安装到 skills 目录。

脚本只读两个工作簿，不改文件。它可以发现题头改动、增行、增表、样式变更和部分公式缓存问题；不能独立证明日期覆盖、数值正确、模型可行或全局最优。填表的完整说明见[交付与同步](skills/cumcm-dialogue/references/delivery-and-sync.md)。

目前的验证包括 skill 格式检查、10 项脚本行为测试和匿名交互场景的前向检查，未进行跨模型、跨客户端的大规模效果评测。

## 开源范围

本仓库仅公开通用流程、通用写作提示词、匿名案例、报告等模板与辅助脚本，不包含赛题原文、原始数据、参赛论文、个人信息或登录凭据。使用时按实际题设、当年竞赛规则和团队要求调整。
